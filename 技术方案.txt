## 军训模拟器全栈技术方案（优化版）

### 1. 项目概述

**军训模拟器**是一款基于选择的文字冒险游戏。玩家扮演一名参加军训的学生，在7天的军训生活中通过做出不同选择，影响体力、纪律、心情、教官好感、同学关系等属性，最终根据表现获得不同的正能量结局。

本方案采用前后端分离架构，前端负责渲染与交互，后端负责游戏逻辑与数据持久化，数据库存储用户、存档、事件库和结局库。

---

### 2. 技术栈选型

| 层级 | 技术 | 说明 |
|------|------|------|
| 前端 | React 18 + TypeScript | 组件化开发，类型安全 |
| 前端状态管理 | Zustand | 轻量，适合游戏状态 |
| UI 样式 | Tailwind CSS | 快速实现主题切换、响应式设计 |
| 前端构建 | Vite | 快速开发与打包 |
| 后端 | Python 3.11 + FastAPI | 高性能异步框架，自动生成 OpenAPI 文档 |
| 后端游戏逻辑 | 复用现有 Python 类 | 属性系统、事件库、结局库等 |
| 数据库 | PostgreSQL 15 | 关系型数据库，支持 JSONB 存储灵活数据 |
| ORM | SQLAlchemy 2.0 (async) | 异步数据库操作 |
| 认证 | JWT (PyJWT) | 无状态认证 |
| 缓存（可选） | Redis | 存储会话、热点数据 |
| 部署 | 前端：Vercel / 静态托管；后端：Docker + 云服务器 | 快速部署，易于扩展 |

### 5. 数据库设计

#### 5.1 用户表 `users`
```sql
CREATE TABLE users (
    id SERIAL PRIMARY KEY,
    username VARCHAR(50) UNIQUE NOT NULL,
    password_hash VARCHAR(255) NOT NULL,
    created_at TIMESTAMP DEFAULT NOW()
);
```

#### 5.2 存档表 `saves`
```sql
CREATE TABLE saves (
    id SERIAL PRIMARY KEY,
    user_id INTEGER NOT NULL REFERENCES users(id) ON DELETE CASCADE,
    slot INTEGER NOT NULL DEFAULT 1,           -- 存档槽位
    save_data JSONB NOT NULL,                  -- 完整玩家状态
    created_at TIMESTAMP DEFAULT NOW(),
    updated_at TIMESTAMP DEFAULT NOW(),
    UNIQUE(user_id, slot)
);
```

#### 5.3 事件库表 `events`
```sql
CREATE TABLE events (
    id VARCHAR(50) PRIMARY KEY,
    event_data JSONB NOT NULL,                 -- 事件完整定义
    category VARCHAR(50),                      -- 分类：training, rest, special等
    active BOOLEAN DEFAULT TRUE
);
```

#### 5.4 结局库表 `endings`
```sql
CREATE TABLE endings (
    id VARCHAR(50) PRIMARY KEY,
    ending_data JSONB NOT NULL
);
```

#### 5.5 角色预设表 `characters`
```sql
CREATE TABLE characters (
    id VARCHAR(50) PRIMARY KEY,                -- 例如 "instructor", "head_teacher"
    name VARCHAR(50) NOT NULL,
    role VARCHAR(30),
    initial_data JSONB NOT NULL
);
```

> 事件库、结局库、角色预设也可直接作为静态 JSON 文件由后端加载，但放入数据库便于动态更新和管理。

### 6. 后端 API 设计

所有 API 均以 `/api` 为前缀，除登录注册外均需 `Authorization: Bearer <JWT>`。

#### 6.1 认证相关
| 方法 | 路径 | 请求体 | 响应 | 说明 |
|------|------|--------|------|------|
| POST | `/api/auth/register` | `{username, password}` | `{message}` | 注册新用户 |
| POST | `/api/auth/login` | `{username, password}` | `{access_token, token_type}` | 登录获取 JWT |

#### 6.2 游戏相关
| 方法 | 路径 | 请求体 | 响应 | 说明 |
|------|------|--------|------|------|
| POST | `/api/game/start` | `{slot?: number}` | `GameState` | 开始新游戏，返回初始状态 |
| POST | `/api/game/choose` | `{option_index: number}` | `GameState` | 提交选择，返回更新后状态 |
| GET | `/api/game/state` | - | `GameState` | 获取当前游戏状态（内存或数据库） |
| GET | `/api/game/events` | - | `Event[]` | 获取事件库（调试用） |
| POST | `/api/game/save` | `{slot: number}` | `{message}` | 保存当前状态到数据库 |
| GET | `/api/game/load` | `{slot: number}` | `GameState` | 从数据库读取存档 |
| GET | `/api/game/endings` | - | `Ending[]` | 获取结局库（或判定当前结局） |

**GameState 结构示例：**
```json
{
  "player": {
    "attributes": {"stamina": 75, "discipline": 60, ...},
    "flags": {"has_uniform": true, "formation": "normal", ...},
    "inventory": {...},
    "relationships": {...}
  },
  "day": 3,
  "phase": "training",
  "current_event": {
    "id": "train_junzi",
    "title": "军姿训练",
    "description": "……",
    "options": [
      {"text": "纹丝不动", "effects": {...}},
      {"text": "偷懒", "effects": {...}}
    ]
  },
  "ending": null   // 若游戏结束，此处为结局列表
}
```

### 7. 游戏引擎实现要点

后端集成之前编写的 `AttributeSystem`、`Character`、事件库和结局库。核心流程：

```python
class GameEngine:
    def __init__(self):
        self.events = load_events()          # 从数据库或JSON加载
        self.endings = load_endings()
        self.active_games = {}               # user_id -> GameState (内存缓存)

    def start_new_game(self, user_id):
        player = Character(...)              # 初始化角色
        state = GameState(player, day=1, phase="morning")
        self.active_games[user_id] = state
        return self._advance(state)

    def choose_option(self, user_id, option_index):
        state = self.active_games.get(user_id)
        if not state:
            raise GameNotFound()
        event = state.current_event
        option = event.options[option_index]
        # 应用效果
        apply_effects(state.player, option.effects)
        # 检查属性是否触发特殊事件（如中暑）
        # 推进时间
        state.advance_phase()
        # 获取下一个事件
        next_event = self._get_next_event(state)
        state.current_event = next_event
        # 检查游戏是否结束
        if state.day > 7:
            state.ending = generate_ending(state.player)
        return state
```

- **事件筛选**：根据当前 `day`、`phase`、属性、标记，从事件库中筛选满足条件的事件，按权重随机选取。
- **时间推进**：每天包含 `morning`、`training`、`noon`、`training`、`rest`、`evening`、`night` 等阶段，每阶段处理一个事件。
- **状态持久化**：定时或在存档时，将 `GameState` 序列化为 JSONB 存入 `saves` 表。

### 8. 前端界面与交互

- **游戏主界面**：
  - 顶部属性栏：体力、纪律、心情、健康、口渴度等以进度条显示。
  - 中央事件卡片：显示事件标题、描述，下方为选项按钮。
  - 选项按钮点击后调用 `POST /api/game/choose`，更新状态并刷新界面。
  - 支持主题切换（对应后端风格设定）。
- **结局页**：展示多个正能量结局卡片，带有动画效果。
- **存档管理**：提供保存、读取槽位界面。

### 9. 安全与性能

- **安全**：
  - 密码使用 bcrypt 哈希。
  - JWT 设置合理过期时间（如 7 天）。
  - API 输入验证（Pydantic）。
  - 防止 SQL 注入（ORM 参数化查询）。
- **性能**：
  - 游戏状态在内存中缓存（Redis 可选），避免频繁数据库读写。
  - 事件库和结局库在启动时加载到内存。
  - 使用异步 FastAPI 处理高并发请求。
  - 数据库索引：`saves(user_id)`，`events(category)`。

---

### 10. 部署方案

- **前端**：构建为静态文件，部署到 Vercel、Netlify 或 Nginx。
- **后端**：使用 Docker 容器化，部署到云服务器（如阿里云 ECS、AWS EC2）。配置环境变量（数据库连接、密钥等）。
- **数据库**：可使用云数据库（如阿里云 RDS PostgreSQL）或服务器自建。
- **反向代理**：Nginx 配置 SSL，转发 `/api` 到后端服务。

---

### 11. 扩展性

- **事件热更新**：修改数据库中的事件库即可，无需重新部署。
- **多平台**：前端可打包为移动端应用（React Native 或 PWA）。
- **社交功能**：增加排行榜、分享结局等功能。
- **多语言**：前端 i18n，后端事件库支持多语言字段。

---

### 12. 备选轻量方案

若无需用户系统，可简化为：
- **前端**：纯 HTML + JavaScript，使用 localStorage 存档。
- **后端**：Python FastAPI 仅作为 API 服务，提供事件和结局数据，不管理用户。
- **数据库**：SQLite 存储事件，或直接静态 JSON。
